# T1 · ChnSentiCorp 中文情感二分类

> 任务难度 **★★** ｜ Oracle 自动化率 **90%** ｜ 预实验先锋任务
> 硬性约束：**10 分钟超时** ｜ **100K token 预算**

## 一、任务定位

对 ChnSentiCorp 中文酒店评论语料进行情感二分类（正面 1／负面 0）。本任务为 Harness-NLP-Benchmark 的**预实验先锋任务＋兼容性测试任务＋成功率保底任务**：验证 pipeline 通畅性、实测单次成本、为整组评测提供成功率基线。

## 二、数据说明

- **数据集**：ChnSentiCorp，中文酒店评论情感语料，全量约 1 万条
- **标签体系**：正负二分类（正面 1／负面 0），gold standard 为现成人工标注
- **输入文件**：`input/t1_input.json`（位于你的工作区内）
- **输入格式**：JSON 数组，每条记录仅含两个字段：

```json
[
  {"text_id": 1, "raw_text": "这家酒店很好"},
  {"text_id": 2, "raw_text": "房间太脏了"}
]
```

- **重要**：输入文件**不含 gold_label**。gold 标签存放在评分阶段独立读取的受保护位置，你在运行期间无法获取，也不应尝试获取；你的预测必须基于文本内容本身。

## 三、数据清洗规范（不强制清洗，最小干预原则）

数据集本身为标准数据集，已做过基础清洗。规则如下：

| 规则 | 要求 |
|:---|:---|
| **禁止去除停用词** | 中文否定词（如"不""没"）常被列为停用词，去除会反转句意（如"不是很好看"→"很好看"） |
| **禁止强制分词** | 若你认为分词有助于分类，可在报告中声明所用方案，但非强制 |
| **仅允许** | 去除明显的 HTML 标签残留（若存在） |
| **报告要求** | 若执行任何预处理，必须在 `t1_error_analysis.md` 中声明具体步骤 |

## 四、执行步骤

**Step 1 读取数据**
- 读取 ChnSentiCorp 输入文件（不含 gold_label）
- 确认样本数量与正负分布（按输入数据统计；gold 不可用，基于你的方法对输入的判定口径统计即可）

**Step 2 【可选】文本预处理**
- 仅允许去除 HTML 标签残留
- 禁止去除停用词、禁止强制分词
- 若执行预处理，记录具体步骤供 evaluator 检查（写入 `t1_error_analysis.md`）

**Step 3 情感二分类**
- 对每条评论预测情感标签（正面 1／负面 0）
- 方法不限：LLM API／本地模型／规则／机器学习均可

**Step 4 统计结果**
- 计算 accuracy、precision、recall、F1
- 计算混淆矩阵（TP／FP／FN／TN）
- 统计正负样本预测比例

**Step 5 错误分析**
- 筛选分类错误的样本（自行对比 pred_label 与自身判断逻辑）
- 对错误案例分类（如否定词误读／领域术语／口语表达等）
- 提出具体改进建议

**Step 6 产出五个文件**
- 五个文件**缺一不可**，格式见第五节，统一放在工作区根目录

## 五、输出文件规范（五个独立文件，缺一不可）

### 文件 1：`t1_classification.json`

- 格式：JSON 数组
- 必须字段：
  - `text_id`：整数，原数据有则用原 id，无则用行号
  - `raw_text`：字符串，原始评论文本
  - `pred_label`：整数（0 或 1），Agent 预测标签

```json
[
  {"text_id": 1, "raw_text": "这家酒店很好", "pred_label": 1},
  {"text_id": 2, "raw_text": "房间太脏了", "pred_label": 0}
]
```

### 文件 2：`t1_metrics.json`

- 格式：JSON 对象
- 必须字段：`accuracy`、`precision`、`recall`、`f1`（均为浮点数）

```json
{
  "accuracy": 0.8765,
  "precision": 0.8823,
  "recall": 0.8691,
  "f1": 0.8756
}
```

### 文件 3：`t1_confusion_matrix.json`

- 格式：JSON 对象
- 必须字段（均为整数）：
  - `tp_count`：整数（实际正面，预测正面）
  - `fp_count`：整数（实际负面，预测正面）
  - `fn_count`：整数（实际正面，预测负面）
  - `tn_count`：整数（实际负面，预测负面）

```json
{
  "tp_count": 3500,
  "fp_count": 450,
  "fn_count": 550,
  "tn_count": 4500
}
```

### 文件 4：`t1_distribution.json`

- 格式：JSON 对象
- 必须字段：
  - `pred_positive_count`：整数，预测为正面的样本数
  - `pred_negative_count`：整数，预测为负面的样本数
  - `pred_positive_ratio`：浮点数，预测正面占比

```json
{
  "pred_positive_count": 3950,
  "pred_negative_count": 5050,
  "pred_positive_ratio": 0.4389
}
```

### 文件 5：`t1_error_analysis.md`

- 格式：Markdown
- 必须包含三部分：
  1. **错误样本清单**：至少 5 条典型案例（含 text_id、raw_text、pred_label、错误原因简述）
  2. **错误类型分类**：将错误案例按类型归类（如否定词误读／领域术语／口语表达／长度偏差等）
  3. **改进建议**：针对每类错误提出具体、可操作的改进方向
- 若执行过任何预处理，在此声明具体步骤

## 六、评分标准

你的产出将由以下标准自动评分：

- **格式合规性（30%）**：五个输出文件是否齐全、字段是否正确、JSON 语法是否合法
- **分类准确率（70%）**：预测标签（pred_label）与正确答案的匹配比例

请确保输出格式严格符合规范，格式错误会直接导致大量扣分。

另有 Judge 评分（10 分），依据 rubric.md 评定报告完整性、统计指标计算正确性（自报指标将与独立重算结果比对，误差<1% 视为一致）、格式规范性、可读性与分析深度；错误分析敷衍会在该部分被扣分。
