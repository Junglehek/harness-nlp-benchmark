## 三、测试 5 端到端验证（三次独立运行）

### 3.1 背景

测试 5 为 T1 冒烟测试最后一项，验证 evaluator + judge + 全量 gold 能串起来，总分计算正确。共独立跑 3 次，既证明稳定性又证明容错。

### 3.2 执行命令

```bash
cd /Users/Apple/Desktop/DownTheRoad/Harness对比小尝试/harness-nlp-benchmark/tasks/t1_chnsenticorp

# Step 1: 重置工作区
bash fixtures/reset_workspace.sh

# Step 2: 确认 input 已就位
ls runs/t1/run_default/input/t1_input.json

# Step 3: 生成 7766 条完美答案（从 gold 提取，确保 accuracy=1.0）
python3 -c "
import json
with open('fixtures/t1_gold.json') as f:
    gold = json.load(f)
perfect = [{'text_id': g['text_id'], 'raw_text': g['raw_text'], 'pred_label': g['gold_label']} for g in gold]
with open('runs/t1/run_default/t1_classification.json', 'w') as f:
    json.dump(perfect, f, ensure_ascii=False, indent=2)
print(f'生成完美答案: {len(perfect)} 条')
"

# Step 4: 造其余 4 个文件
cat > runs/t1/run_default/t1_metrics.json << 'EOF'
{"accuracy": 1.0, "precision": 1.0, "recall": 1.0, "f1": 1.0}
EOF

cat > runs/t1/run_default/t1_confusion_matrix.json << 'EOF'
{"tp_count": 3883, "fp_count": 0, "fn_count": 0, "tn_count": 3883}
EOF

cat > runs/t1/run_default/t1_distribution.json << 'EOF'
{"pred_positive_count": 3883, "pred_negative_count": 3883, "pred_positive_ratio": 0.5}
EOF

cp smoke_test_data/t1_error_analysis_good.md runs/t1/run_default/t1_error_analysis.md

# Step 5: 跑 evaluator
python3 evaluator.py --run-dir ./runs/t1/run_default --gold ./fixtures/t1_gold.json

# Step 6: 跑 judge
python3 judge.py --run-dir ./runs/t1/run_default --repeat 3

# Step 7: 验证总分
python3 -c "
import json
a = json.load(open('runs/t1/run_default/t1_autoscore.json'))['auto_total']
j = json.load(open('runs/t1/run_default/t1_judgescore.json'))['judge_score_10']

print(f'Judge 分: {j}/10')
print(f'总分: {a+j}/100')
```

### 3.7 统计分析

**自动分一致性**：三次均为 90.00/90，证明 Oracle 层完全确定性。

**Judge 分变异分析**：

| 指标 | 数值 |
|:---|:---:|
| Judge 分范围 | 6.08 – 6.60 |
| Judge 分均值 | 6.39 / 10 |
| Judge 分标准差 | 0.27 |
| 变异系数 (CV) | 4.2% |

即使 temperature=0，三次 Judge 分仍有 0.52 分自然变异，验证 median_of_3 设计必要性。

**五维度稳定性**：

| 维度 | 第1次 | 第2次 | 第3次 | 变异范围 |
|:---|---:|---:|---:|:---|
| 报告完整性 | 45 | 45 | 42 | 42–45 |
| 统计指标计算正确性 | 88 | 85 | 79 | 79–88 |
| 格式规范性 | 80 | 85 | 77 | 77–85 |
| 可读性 | 65 | 72 | 66 | 65–72 |
| 分析深度 | 25 | 28 | 25 | 25–28 |

### 3.8 median_of_3 容错机制验证

| 场景 | 第1次 | 第2次 | 第3次 |
|:---|:---:|:---:|:---:|
| 3 次全成功 | ✅ | ✅ | ❌ |
| 2 次成功取 median | — | — | ✅ |
| 结果可用性 | 可用 | 可用 | 可用 |

**结论**：
- 前两次证明：网络稳定时，3 次调用全部成功，median_of_3 不影响正常评分
- 第三次证明：网络瞬断时，median_of_3 自动兜底，2 次成功即可产出有效中位数
- 三次均产出可用 Judge 分，median_of_3 机制在两种场景下均验证通过

### 3.9 方法论意义

| 证明目标 | 证据 |
|:---|:---|
| **系统稳定性** | 第 1、2 次 3/3 全成功，evaluator 自动分三次一致 90.00 |
| **评分一致性** | 三次总分 96.08–96.60，变异 < 0.6%，系统可复现 |
| **容错机制有效性** | 第 3 次 1/3 失败，median_of_3 兜底成功，结果仍可用 |
| **median_of_3 必要性** | 即使 temperature=0，Judge 分仍有 4.2% 变异，单次评分不可靠 |
| **网络层独立性** | 自动分不受网络影响（三次一致），Judge 分受网络影响但已被兜底 |
